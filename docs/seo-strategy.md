# SEO strategy

## Canonical host

`https://www.mabglobalpartners.com`, configured through `NEXT_PUBLIC_SITE_URL` (`src/config/site.ts`). On 2026-10-12 the apex domain already redirected to `www` at the Vercel domain level. Keep that redirect in the Vercel domain settings; the application does not duplicate it.

`absoluteUrl()` (`src/lib/seo/canonical.ts`) builds every absolute URL. It removes query strings, fragments and trailing slashes, so tracking parameters never create alternative canonicals.

## Indexing rules

* Production only: `VERCEL_ENV=production` or `SITE_ENV=production`.
* Any other deployment (preview, local) renders `noindex, nofollow`, an empty sitemap and `Disallow: /` in robots.txt.
* `/api/*` is disallowed in robots.txt and sends `X-Robots-Tag: noindex, nofollow`.
* The 404 page is `noindex`. Unknown URLs return a real 404 status, including unknown article slugs (handled in `src/proxy.ts`, see `architecture.md`).

## Metadata

`buildMetadata()` (`src/lib/seo/metadata.ts`) produces title, description, canonical, robots, Open Graph (type, locale `en_US`, site name, URL, title, description, image) and X card fields. Static pages read their values from `src/content/pages.ts`; services, sectors and articles from their registries. No page hardcodes metadata.

Next.js merges `openGraph` and `twitter` objects shallowly, so the shared images generated by `src/app/opengraph-image.tsx` and `twitter-image.tsx` are referenced explicitly in every page's metadata. Tests assert unique titles and descriptions, description length between 70 and 170 characters, canonical URLs on the production host and social images on every page.

## Sitemap

`src/app/sitemap.ts` maps `collectSitemapRecords()` (`src/lib/seo/sitemap-utils.ts`) to absolute URLs. Records come from the published registries, so new published services, sectors and articles are included automatically and drafts never are. `lastModified` uses content `updatedAt` dates. The current site has 26 URLs; a sitemap index (`generateSitemaps`) becomes worthwhile above several thousand URLs.

## robots.txt

`src/lib/seo/robots.ts`:

```text
User-Agent: *
Allow: /
Disallow: /api/

User-Agent: OAI-SearchBot / Claude-SearchBot / PerplexityBot      (allow, /api/ blocked)
User-Agent: ChatGPT-User / Claude-User / Perplexity-User          (allow, /api/ blocked)
User-Agent: GPTBot / ClaudeBot / Google-Extended / Applebot-Extended / CCBot  (allow by default, configurable)

Sitemap: https://www.mabglobalpartners.com/sitemap.xml
```

Static assets under `/_next/` remain crawlable. See `llm-discoverability.md` for the AI crawler policy.

## Structured data

Generated in `src/lib/seo/structured-data.ts` and rendered with `src/components/seo/json-ld.tsx` (with `<` escaped).

| Page | Types |
|---|---|
| Homepage | Organization, WebSite, WebPage, FAQPage |
| Service | Organization, WebPage, BreadcrumbList, Service, FAQPage |
| Sector | Organization, WebPage, BreadcrumbList, FAQPage |
| Article | Organization, WebPage, BreadcrumbList, Article (with `citation`) |
| About, contact, index pages | Organization, AboutPage / ContactPage / CollectionPage, BreadcrumbList |
| Legal | WebPage, BreadcrumbList |

The Organization node contains name, URL, logo, description, email, postal address, a Place with the Google Maps link, ContactPoint, founder and areaServed. It intentionally omits telephone, legal name, tax ID, founding date, social profiles, ratings and reviews, because none are verified. `LocalBusiness` is not used: no verified opening hours or local service model exist for this brand.

FAQPage markup is valid schema for visible FAQ content. Google limits FAQ rich results to a small set of sites, so treat it as semantic markup, not a rich result source.

Validation done: JSON parsing and type checks in unit and end-to-end tests. Before launch, check the production URLs with the Schema.org validator (validator.schema.org) and Google's Rich Results Test; both need public URLs and could not be run against localhost.

## Internal linking

* Header and footer link every service, the indexes and the legal pages.
* Services link related services and sectors; sectors link their services; articles link related services; every inner page has breadcrumbs and a consultation CTA.
* `tests/e2e/pages.spec.ts` fails if any internal link on any sitemap page points outside the sitemap.

## URL conventions

Lowercase English slugs, hyphen separated: `/services/us-company-formation`, `/industries/export-and-logistics`, `/insights/us-company-formation-guide`. The Turkish slugs used before 2026-10-12 were never public, so no redirects exist for them. Changing a published slug requires a permanent redirect in `next.config.ts` (`redirects()`).
