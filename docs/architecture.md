# Architecture

## Stack

| Layer | Choice | Notes |
|---|---|---|
| Framework | Next.js 16.4 App Router, React 19.3 | Scaffolded with `create-next-app` (greenfield repository) |
| Rendering | Cache Components + Partial Prefetching | Defaults of the 16.4 scaffold, kept on purpose |
| Language | TypeScript (strict) | Route types generated by `next typegen` |
| Styling | Tailwind CSS 4 via `@tailwindcss/turbopack` | Brand tokens in `src/styles/tokens.css` |
| Fonts | TeX Gyre Adventor (headings, `next/font/local`) and Figtree (text, `next/font/google`) | Free equivalents of the Century Gothic and Proxima Nova used on behringeb5.com (client reference, 2026-10-12); both self-hosted at build time |
| Validation | zod 4 | One schema shared by the form and the API |
| Icons | lucide-react | Tree-shaken per icon |
| Tests | Vitest 5, Playwright 1.63, axe-core | See `README.md` |

No database, CMS, state library or UI kit is used. Content is typed TypeScript in the repository, which is the simplest model that satisfies the current scope. A CMS can replace the content modules later without touching templates (see `content-model.md`).

## Folder organization

```text
src/
  app/                 Routes, metadata routes and route handlers only
  components/
    layout/            Header, navigation, footer, breadcrumb, logo
    sections/          Homepage and shared page sections
    services/          Service card and service page template
    sectors/           Sector card and sector page template
    knowledge/         Article card and article template
    legal/             Legal page template
    forms/             Contact form (client component)
    seo/               JSON-LD renderer
    ui/                Small primitives (buttons, headings, icons, lists)
  config/              Site, contact, brand, routes, SEO policy
  content/             Typed content registries (services, sectors, FAQs, articles, pages, legal)
  lib/
    seo/               Canonical URLs, metadata, structured data, robots, sitemap records
    llms/              llms.txt and llms-full.txt generators
    contact/           Contact request pipeline and email delivery
    validation/        Contact schema, limits and options
    security/          Rate limiting
    utilities/         Small pure helpers

```

The reference structure in the brief used a `(website)` route group. It was not added because the site has a single layout; a group would add a folder without changing behavior.

## Routing

* Services (`/services/*`) and industries (`/industries/*`, called sectors in the code) are explicit folders. Each `page.tsx` is a three-line wrapper around the shared template, keyed by slug. Explicit folders give fully static pages and real 404s for unknown URLs without request-time work. `tests/unit/routes-and-content.test.ts` fails if a registry entry lacks a page or a page lacks a sitemap entry.
* Articles use `bilgi-merkezi/[slug]` with `generateStaticParams`, so new articles need no new files. Under Partial Prefetching an unlisted slug would stream the shared shell with a 200 status (soft 404), so `src/proxy.ts` rewrites unknown slugs to an unmatched path before rendering, which returns a real 404.
* `/api/contact` is the only dynamic route.
* `sitemap.xml`, `robots.txt`, `manifest.webmanifest`, `llms.txt`, `llms-full.txt`, Open Graph and icon images are generated from the same registries at build time.

## Rendering decisions

* Every page is prerendered (`○` in the build output). Content pages are Server Components; the only client components are the desktop navigation active state, the mobile menu, the contact form and the error boundary.
* The copyright year is a `"use cache"` component with `cacheLife("days")`, because Cache Components forbids `new Date()` in prerendered output.
* `usePathname()` consumers are wrapped in `<Suspense>` with a static fallback so the App Shell never depends on the URL.
* The contact form loads the zod validator on first focus. Without this, Partial Prefetching of the contact page pulled a 115 KB chunk into every page that links to it.
* FAQ accordions use native `<details>/<summary>`: keyboard accessible, no JavaScript, answers present in the HTML.
* The mobile menu uses `<dialog>.showModal()` for focus containment, Escape handling and an inert background.

## Design system

The hero and header follow the consulting reference supplied on 2026-10-12 ("Consultare"): a full-bleed navy hero with the transparent header laid over it, wordmark and links on the left and a white "Get in Touch" button on the right, an uppercase label with a dot, a large two-line white heading, a one-line description and a white primary button next to a translucent secondary button, anchored bottom left. The architectural image fills the right side; its sky is the same navy as the section. Inner pages open with a matching navy band. The sections below follow the earlier one-page law-firm reference: small framed labels above section headings, grouped services shown as stacked framed rows with one opened card, staggered process boxes marked with their own framed icons, a profile block with verified figures, working principles with one navy call-to-action card, framed FAQ boxes, a contact band with icons framed like the buttons and a framed request card. Inner pages follow the homepage (client decision, 2026-10-13): every page opens with the same navy hero (large bold title, one line, a white "Schedule a Consultation" button with a calendar icon and an outlined white button, the architectural image on the right on wide screens); the Services, Industries and Insights indexes show their items in the homepage tile grid (`TileBand`, white tone under the navy hero); service and industry pages end with a navy "Related Services" tile band like the homepage services band. The About block and the service, industry and About overviews use a framed feature panel after the analytics reference supplied on 2026-10-12: uppercase label, heading, two feature columns and a text link with a round arrow on the left, an image with framed fact cards (rows split by dashed lines) on the right. The footer follows the footer reference supplied the same day: a rounded navy panel inset on the white page with the wordmark and a short line on top, link columns and the MAB Registered Agent Inc. sister brand in the middle, and the legal bar at the bottom. No social links are shown because no accounts are confirmed. Buttons and boxes use thin frames, following the button and input styles of brandunder.com and popupsmart.com.

* Colors: `src/styles/tokens.css` resets Tailwind's palette (`--color-*: initial`) so only brand tokens exist. `src/config/brand.ts` mirrors the hex values for generated images; a unit test keeps them identical.
* Surfaces: sections and boxes are white or navy. Boxes use the `frame` utility (1 px `line` border in a light navy tint, soft shadow).
* Navy (client decision, 2026-10-12): the brief's navy #262F40 and deep navy #1C2432 read as grey, so they were replaced with a saturated dark navy (`navy` #12264A, `navy-deep` #0A1A36, `ink` #0D1B33). Gradients over the hero image mix `var(--color-navy-deep)` with `color-mix()`, so a palette change needs no component edits.
* No grey (client decision, 2026-10-12): the brief's slate, muted, light grey, soft grey and border grey tokens are removed from the theme. Text is navy or ink on white and solid white on navy; translucent white text is not used. A unit test fails if a grey token returns.
* Pairing rules (client decision, 2026-10-12): orange fills carry white text only; navy surfaces carry white only; navy is never placed on orange and orange is never placed on navy. Orange appears as the primary button fill, heading accent lines and small icons on white. Navy appears as heading color, filled process and call-to-action boxes, round contact icons and the footer. Navy areas use the `on-dark` utility, which also switches the focus ring and text selection to white.
* Orange surface: the About page philosophy card uses `accent-strong` (#C24A00) with white text, which reaches 4.9:1 (client request, 2026-10-13).
* Contrast exception: white on brand orange (#F45800) is 3.4:1, below the 4.5:1 AA threshold for normal-size text. The client chose this pairing explicitly. Orange buttons carry a `data-brand-accent` attribute and are excluded from the automated axe check in `tests/e2e/pages.spec.ts`; every other element is checked. Orange heading accents are large text (at least 28 px), where 3:1 applies. A darker orange such as #CC4700 would reach 4.7:1 if full AA compliance is required later.
* Logo: vector artwork traced from the client's master file, rendered inline from `src/config/logo.ts` with `currentColor` (white on navy). See docs/content-verification.md.
* Shape: no round buttons (client decision, 2026-10-12); link arrow tiles, toggles and icon frames use the header button radius. Slightly rounded, close-to-square corners (`rounded-card` 12 px, `rounded-panel` 10 px, `rounded-control` 8 px for buttons and inputs, `rounded-chip` 6 px for labels). No decorative lines or underlines.
* Imagery: the hero uses an architectural composite supplied by the client (classical colonnade and a dome). The baked-in transparency checkerboard was removed, the sky was replaced with flat navy-deep (#0A1A36) and the building was toned from deep navy to light blue. The About block uses "National Capitol columns at the United States National Arboretum" by Carol M. Highsmith (Library of Congress, LCCN 2010641854, public domain), toned the same way. Credits appear on the Legal Notice page.
* Typography: headings in TeX Gyre Adventor Bold (GUST Font License; a clone of ITC Avant Garde Gothic, whose proportions Century Gothic matches), text in Figtree (SIL OFL, close to Proxima Nova). Menu items and buttons are bold uppercase with wide tracking, after behringeb5.com. Fluid tokens `text-display` (40 to 65 px), `text-heading` (32 to 50 px), `text-title` (18 to 21 px), `text-body` (16 px), `text-label` (14 px), `text-caption` (13 px). Copy is kept short so headings, card titles and buttons do not wrap unnecessarily; buttons and navigation labels never wrap.
* Spacing: `container-page` (max 1920 px so the layout fills wide screens, 20/32/40/48/64 px gutters) and `section-y` (80/112/136 px vertical padding).
* Fonts on disk: `src/assets/fonts` holds TeX Gyre Adventor as WOFF2 subsets (Basic Latin, Latin-1 and Latin Extended-A, about 29 KB each) for the site, the OpenType masters for the Open Graph image, and the GUST license. `next/font` generates metric-matched Arial fallbacks for both families.

## Security

* Security headers in `next.config.ts`: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`, HSTS (no `includeSubDomains`, because other subdomains exist) and, in production, a static Content-Security-Policy.
* The CSP allows `'unsafe-inline'` scripts because a nonce-based policy would force every page to render per request. All script sources are first-party and there is no user-generated HTML.
* `/api/*` responses carry `X-Robots-Tag: noindex, nofollow`.
* Contact API: same-origin check, JSON-only, 16 KB body limit, honeypot, minimum completion time, per-instance rate limit (5 per 10 minutes per IP), schema validation, HTML escaping in emails, provider idempotency key.
* Secrets are read only on the server. `.env.example` lists names with safe placeholders.
